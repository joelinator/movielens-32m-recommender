\begin{abstract}
Building a recommender system for tens of millions of ratings requires both a solid statistical model and fast data structures. In this paper, we build and study matrix factorization models trained with Alternating Least Squares (ALS) on the full MovieLens-32M dataset ($32{,}000{,}204$ ratings from $200{,}948$ users and $84{,}432$ movies), as well as a smaller $5$-million-rating subset. To store the ratings efficiently in memory, we use two Compressed Sparse Row (CSR) matrices: one indexed by user and one indexed by movie. This setup uses about $513$~MB of RAM and allows us to look up all ratings for any user or movie in constant time. By parallelizing the ALS updates across CPU threads and solving the small linear systems in-place with Cholesky decomposition, our training loop runs nearly $70$ times faster than batched array solvers. We begin by exploring the rating distribution and power-law behavior of users and movies. Next, we compare a simple bias-only model against full matrix factorization with user and movie trait vectors, showing how regularization and the number of latent dimensions $K$ affect test error and overfitting. We also visualize 2D movie embeddings, generate personalized recommendations for a new user who likes \emph{The Lord of the Rings}, and identify the most and least polarizing movies using vector lengths. Finally, we extend the model by adding movie genre information into the prior distribution of movie vectors, which noticeably improves predictions for new and rarely rated movies. Our source code is publicly available at \url{https://github.com/joelinator/movielens-32m-recommender}.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Online platforms such as streaming services and online stores rely on recommender systems to help users find items they might enjoy among tens of thousands of choices \cite{koren2009matrix,harper2015movielens}. One of the most effective approaches to this problem is collaborative filtering, which predicts what a user will like based on past ratings from many users, without needing detailed descriptions of the items themselves.

When working with large datasets like MovieLens-32M, which has over $32$ million ratings across $200{,}948$ users and $84{,}432$ movies, storing the ratings in a standard two-dimensional table is not practical. A full table of size $200{,}948 \times 84{,}432$ using 32-bit floats would take $67.8$~GB of memory, even though $99.81\%$ of the entries are empty because most users only rate a small fraction of the catalog.

Matrix factorization handles this sparsity by representing each user $m$ and each movie $n$ with a short vector of $K$ numbers, $u_m \in \mathbb{R}^K$ and $v_n \in \mathbb{R}^K$, called latent trait vectors \cite{mnih2007probabilistic,koren2009matrix}. A rating is then predicted as the dot product $u_m^\top v_n$ plus baseline user and movie biases. To learn these parameters from observed ratings, two main algorithms are commonly used: Stochastic Gradient Descent (SGD) and Alternating Least Squares (ALS) \cite{zhou2008large}. ALS is especially attractive for large datasets for three reasons:
\begin{enumerate}
    \item It does not require tuning a learning rate, because each update step has an exact closed-form formula.
    \item The regularized loss function is guaranteed to decrease (or stay the same) at every single step.
    \item When all movie vectors are held fixed, each user vector can be updated independently of all other users. Likewise, when user vectors are fixed, all movie vectors can be updated in parallel across CPU cores.
\end{enumerate}

\subsection{Problem Statement and Structure of the Paper}

Our goal is to predict unseen movie ratings accurately at scale while also understanding what the model learns and where it struggles. Following a clear separation between data exploration, modeling, and experimental evaluation, the rest of this paper is organized as follows:
\begin{enumerate}
    \item \textbf{Data Representation and Exploration (\cref{sec:data_topology}):} We show how to store $32$ million ratings compactly in two CSR matrices ($\mathcal{S}_{\text{user}}$ and $\mathcal{S}_{\text{movie}}$) so that both user updates and movie updates run in constant lookup time, and we analyze the rating histogram and user/movie power-law distributions.
    \item \textbf{Models and ALS Optimization (\cref{sec:bias_model}):} We formulate all three of our models and derive their Alternating Least Squares (ALS) update steps in one place: (i) the baseline bias-only model (\cref{sec:bias_model_sub}), (ii) the matrix factorization model with user and movie trait vectors $U$ and $V$ (\cref{sec:latent_als}), and (iii) the genre-regularized matrix factorization model with altered loss function and three-step ALS updates (\cref{sec:genre_model}), together with our parallel in-place Cholesky solver (\cref{sec:fast_cholesky}).
    \item \textbf{Experimental Results (\cref{sec:experiments}):} We present a comprehensive evaluation across both MovieLens-5M and the full MovieLens-32M dataset, including our train/test split, bias-only and matrix factorization RMSE and monotonic loss curves, choice of training iterations, hyperparameter tuning ($\lambda, \gamma, \tau$), choice of best latent dimension $K$ and diminishing returns, runtime speedups on all $32$ million ratings, 2D movie and genre embeddings, \emph{Lord of the Rings} dummy-user recommendations, and most/least polarizing movies.
\end{enumerate}

\section{Data Representation and Exploratory Analysis}
\label{sec:data_topology}

\subsection{Dual Sparse Matrix Structure}
Let $M$ be the number of users and $N$ be the number of movies. The dataset consists of observed ratings $r_{m,n} \in \{0.5, 1.0, \dots, 5.0\}$ for user--movie pairs $(m,n) \in \Omega$, where $\Omega$ is the set of all observed interactions. For each user $m$, we write $\Omega_m = \{n : (m,n) \in \Omega\}$ for the set of movies rated by user $m$. Similarly, for each movie $n$, we write $\Omega^n = \{m : (m,n) \in \Omega\}$ for the set of users who rated movie $n$. The total number of ratings is $|\Omega| = \sum_{m=1}^M |\Omega_m| = \sum_{n=1}^N |\Omega^n|$.

During ALS training, updating user parameters requires looping over all movies rated by each user ($\Omega_m$), while updating movie parameters requires looping over all users who rated each movie ($\Omega^n$). If we only stored the data grouped by user, updating the movies would require either scanning the entire dataset repeatedly or jumping randomly in memory. Using Python lists of lists or dictionaries also uses too much memory and slows down CPU loops.

To make both half-steps fast, we store the ratings in two Compressed Sparse Row (CSR) structures:
\begin{itemize}
    \item \textbf{User-Indexed CSR Matrix ($\mathcal{S}_{\text{user}}$):} Uses three flat arrays: an offset array $p^{(u)}$ of length $M+1$, a movie-index array of length $|\Omega|$, and a rating array of length $|\Omega|$. For any user $m$, their rated movie IDs and ratings sit side-by-side in memory between indices $p^{(u)}_m$ and $p^{(u)}_{m+1}$.
    \item \textbf{Movie-Indexed CSR Matrix ($\mathcal{S}_{\text{movie}}$):} Uses the same layout transposed by movie: an offset array $p^{(v)}$ of length $N+1$, a user-index array of length $|\Omega|$, and a rating array of length $|\Omega|$. For any movie $n$, all users who rated it sit contiguously between indices $p^{(v)}_n$ and $p^{(v)}_{n+1}$.
\end{itemize}
Using 32-bit integers for indices and offsets and 32-bit floats for ratings, storing both CSR views takes $16|\Omega| + 4(M+N+2)$ bytes. As shown in \cref{tab:dataset_summary}, for all $32{,}000{,}204$ ratings in MovieLens-32M, both structures together take only $513.1$~MB of RAM (over $130$ times smaller than a dense matrix) and load from disk in $4.23$~seconds. Because the ratings for any user or movie sit next to each other in memory, the CPU can read them sequentially without pointer-chasing, which makes our training loops much faster.

\cref{fig:dataset_distributions}(a) shows the distribution of star ratings from $0.5$ to $5.0$ on both MovieLens-32M and the 5M subset. The two datasets have almost identical rating proportions (within $0.02\%$ on every bar). Two simple patterns stand out:
\begin{enumerate}
    \item \textbf{Users Tend to Give High Ratings:} The average rating is $\mu = 3.540$ (with standard deviation $\sigma = 1.059$), which is well above the middle of the scale ($2.75$). The most common rating is $4.0$ stars ($26.15\%$ of all ratings, or $8{,}367{,}654$ ratings), followed by $3.0$ stars ($18.92\%$) and $5.0$ stars ($14.36\%$). Very low ratings ($0.5$, $1.0$, and $1.5$ stars combined) make up only $6.26\%$ of the data. This happens because people mostly choose to watch movies they expect to like \cite{koren2009matrix}.
    \item \textbf{Whole Stars Are Used More Than Half Stars:} Every half-star rating ($0.5, 1.5, 2.5, 3.5, 4.5$) appears much less often than the whole-star ratings next to it. For instance, $3.5$ stars is $13.41\%$ of the data, whereas $3.0$ is $18.92\%$ and $4.0$ is $26.15\%$. There are two reasons for this: MovieLens only added half-star ratings in 2003 (older ratings were whole numbers only), and many users naturally prefer round numbers when rating quickly.
\end{enumerate}

\cref{fig:dataset_distributions}(b) plots the degree distribution on a log-log scale: the horizontal axis is the number of ratings $k$, and the vertical axis is how many movies or users have exactly $k$ ratings. Both curves follow a straight line over several orders of magnitude on the log-log plot, which is the signature of a power law $P(k) \propto k^{-\alpha}$ \cite{clauset2009power}. However, movies and users behave very differently on the left side of the plot:
\begin{itemize}
    \item \textbf{Long Tail of Unpopular Movies:} Movie rating counts range from $k=1$ all the way to $k_{\max} = 102{,}929$ (\emph{The Shawshank Redemption (1994)}). Out of $84{,}432$ movies in MovieLens-32M, $16{,}895$ movies have only $1$ rating, and half of all movies have $5$ ratings or fewer (median $= 5.0$), even though the average movie has $379.0$ ratings. Using the standard maximum-likelihood formula for the power-law exponent \cite{clauset2009power} on the tail ($k_{\text{tail}} = 50$),
    \begin{equation}
        \hat{\alpha} = 1 + |\mathcal{T}| \left(\sum_{i \in \mathcal{T}} \ln \frac{k_i}{k_{\text{tail}} - 0.5}\right)^{-1},
        \label{eq:clauset_mle}
    \end{equation}
    gives a slope of $\hat{\alpha}_{\mathcal{I}} = 1.48$ for movies. A small group of blockbuster movies gets most of the ratings, while most of the catalog sits in the sparse long tail.
    \item \textbf{Sharp Cutoff at $k_{\min} = 20$ for Users:} Unlike movies, the user curve in \cref{fig:dataset_distributions}(b) stops suddenly at a vertical line at $k_{\min} = 20$ on MovieLens-32M (minimum $20$, median $73.0$, mean $159.2$, maximum $33{,}332$). This happens because the creators of the MovieLens dataset removed all users with fewer than $20$ ratings before releasing the data \cite{harper2015movielens}. Above $k = 20$, user activity follows a power law with slope $\hat{\alpha}_{\mathcal{U}} = 1.90$. Because of this rule, every user in the dataset has at least $20$ ratings (around $16$ in the training set), whereas thousands of movies have only $1$ or $2$ ratings. This makes cold-start much harder on the movie side than on the user side, which motivates our genre model in \cref{sec:genre_model}.
\end{itemize}

\section{Models and Optimization}
\label{sec:bias_model}

In this section, we present all three models developed in this paper and derive their Alternating Least Squares (ALS) optimization steps: (1) the baseline bias-only model, (2) the matrix factorization model with user and movie trait vectors $U$ and $V$, and (3) the genre-regularized matrix factorization model that incorporates movie genre metadata into the item prior, followed by our parallel in-place Cholesky implementation.

\subsection{Bias-Only Model}
\label{sec:bias_model_sub}

Before learning latent vectors, it is helpful to build a simple baseline model that captures general rating habits. Some users are generous and give high scores to almost everything ($a_m > 0$), while others are strict critics ($a_m < 0$). Likewise, popular classics get high scores from most viewers ($b_n > 0$), while weak movies get low scores ($b_n < 0$). The bias-only model predicts:
\begin{equation}
    \hat{r}_{m,n} = \mu + a_m + b_n,
    \label{eq:bias_model_pred}
\end{equation}
where $\mu$ is the average training rating ($\mu = 3.5404$ on MovieLens-32M), $a_m \in \mathbb{R}$ is the bias of user $m$, and $b_n \in \mathbb{R}$ is the bias of movie $n$.

From a Bayesian viewpoint, we assume Gaussian rating noise $r_{m,n} \sim \mathcal{N}(\mu + a_m + b_n, \lambda^{-1})$ with precision $\lambda > 0$, and zero-mean Gaussian priors $a_m \sim \mathcal{N}(0, \gamma^{-1})$ and $b_n \sim \mathcal{N}(0, \gamma^{-1})$ with regularization strength $\gamma > 0$. Taking the negative log-posterior (dropping constants) gives the regularized squared-error loss function:
\begin{align}
    \mathcal{L}(a, b) &= \frac{\lambda}{2} \sum_{(m,n) \in \Omega^{\text{train}}} \left(r_{m,n} - \mu - a_m - b_n\right)^2 \nonumber \\
    &\quad + \frac{\gamma}{2} \sum_{m=1}^M a_m^2 + \frac{\gamma}{2} \sum_{n=1}^N b_n^2.
    \label{eq:bias_objective}
\end{align}

To minimize $\mathcal{L}(a,b)$ with Alternating Least Squares, we alternate between fixing $b$ to solve for $a$, and fixing $a$ to solve for $b$. Taking the derivative of $\mathcal{L}(a,b)$ with respect to $a_m$ and setting it to zero gives the exact update for user $m$:
\begin{equation}
    a_m \leftarrow \frac{\lambda \sum_{n \in \Omega_m^{\text{train}}} \left(r_{m,n} - \mu - b_n\right)}{\lambda |\Omega_m^{\text{train}}| + \gamma}.
    \label{eq:user_bias_closed}
\end{equation}
Similarly, holding $a$ fixed and setting $\partial \mathcal{L} / \partial b_n = 0$ gives the exact update for movie $n$:
\begin{equation}
    b_n \leftarrow \frac{\lambda \sum_{m \in \Omega_{\text{train}}^n} \left(r_{m,n} - \mu - a_m\right)}{\lambda |\Omega_{\text{train}}^n| + \gamma}.
    \label{eq:item_bias_closed}
\end{equation}
Notice how the regularization parameter $\gamma$ works in \cref{eq:item_bias_closed}: if we write $\bar{e}_n = \frac{1}{|\Omega_{\text{train}}^n|} \sum_{m \in \Omega_{\text{train}}^n} (r_{m,n} - \mu - a_m)$ for the average residual on movie $n$, then
\begin{equation}
    b_n = \left(\frac{|\Omega_{\text{train}}^n|}{|\Omega_{\text{train}}^n| + \gamma / \lambda}\right) \bar{e}_n.
\end{equation}
When a movie has thousands of ratings ($|\Omega_{\text{train}}^n| \gg \gamma / \lambda$), the fraction is close to $1$ and $b_n \approx \bar{e}_n$. When a movie has only $1$ or $2$ ratings, the denominator pulls $b_n$ closer to $0$ so the model does not trust a single noisy rating too much.

We also note a useful sanity check for our dual CSR data structures: computing the sum of squared errors by looping over users ($\mathcal{S}_{\text{user}}$) must give the exact same number as looping over movies ($\mathcal{S}_{\text{movie}}$), because both sums add up the exact same set of training ratings $\Omega^{\text{train}}$ in a different order:
\begin{align}
    \mathcal{L}_{\mathcal{U}}(a,b) &= \frac{\lambda}{2} \sum_{m=1}^M \sum_{n \in \Omega_m^{\text{train}}} (r_{m,n} - \hat{r}_{m,n})^2 + \mathcal{R}(a,b) \nonumber \\
    &= \frac{\lambda}{2} \sum_{n=1}^N \sum_{m \in \Omega_{\text{train}}^n} (r_{m,n} - \hat{r}_{m,n})^2 + \mathcal{R}(a,b) \nonumber \\
    &= \mathcal{L}_{\mathcal{I}}(a,b),
    \label{eq:fubini_invariance}
\end{align}
where $\hat{r}_{m,n} = \mu + a_m + b_n$ and $\mathcal{R}(a,b) = \frac{\gamma}{2}(\|a\|_2^2 + \|b\|_2^2)$.

\subsection{Matrix Factorization with User and Movie Trait Vectors}
\label{sec:latent_als}

The bias-only model treats all users as if they agree on which movies are good or bad, differing only by a constant offset. To model personal taste (for example, liking sci-fi vs.\ romance), we add a $K$-dimensional latent vector $u_m \in \mathbb{R}^K$ for each user and $v_n \in \mathbb{R}^K$ for each movie \cite{mnih2007probabilistic,koren2009matrix}:
\begin{equation}
    \hat{r}_{m,n} = \mu + a_m + b_n + u_m^\top v_n, \quad u_m, v_n \in \mathbb{R}^K.
    \label{eq:pmf_pred}
\end{equation}
We place independent zero-mean Gaussian priors $u_m \sim \mathcal{N}(\mathbf{0}, \tau^{-1} I_K)$ and $v_n \sim \mathcal{N}(\mathbf{0}, \tau^{-1} I_K)$ on the trait vectors with regularization parameter $\tau > 0$. The full regularized loss function over $\Theta = \{a, b, U, V\}$ is:
\begin{align}
    \mathcal{L}(\Theta) &= \frac{\lambda}{2} \sum_{(m,n) \in \Omega^{\text{train}}} \left(r_{m,n} - \mu - a_m - b_n - u_m^\top v_n\right)^2 \nonumber \\
    &\quad + \frac{\gamma}{2} \left(\sum_{m=1}^M a_m^2 + \sum_{n=1}^N b_n^2\right) \nonumber \\
    &\quad + \frac{\tau}{2} \left(\sum_{m=1}^M \|u_m\|_2^2 + \sum_{n=1}^N \|v_n\|_2^2\right).
    \label{eq:pmf_full_loss}
\end{align}

Because $u_m^\top v_n$ multiplies two unknowns together, $\mathcal{L}(\Theta)$ is not convex when $U$ and $V$ vary at the same time. However, if we hold the movie parameters $(b, V)$ fixed, $\mathcal{L}(\Theta)$ becomes a simple quadratic function of $(a_m, u_m)$ for each user $m$ separately. Setting the derivatives with respect to $a_m$ and $u_m$ to zero (see \cref{app:derivations} for the step-by-step derivation) gives the user updates:
\begin{align}
    a_m &\leftarrow \frac{\lambda \sum_{n \in \Omega_m^{\text{train}}} \left(r_{m,n} - \mu - b_n - u_m^\top v_n\right)}{\lambda |\Omega_m^{\text{train}}| + \gamma}, \label{eq:pmf_user_bias} \\
    u_m &\leftarrow \left(\lambda \sum_{n \in \Omega_m^{\text{train}}} v_n v_n^\top + \tau I_K\right)^{-1} \!\! \left(\lambda \sum_{n \in \Omega_m^{\text{train}}} \tilde{r}_{m,n}^{(u)} v_n\right), \label{eq:pmf_user_vec}
\end{align}
where $\tilde{r}_{m,n}^{(u)} = r_{m,n} - \mu - a_m - b_n$ is the rating residual after subtracting the biases.

In the second half of each ALS iteration, we hold $(a, U)$ fixed and update each movie's bias $b_n$ and trait vector $v_n$ using the movie-indexed CSR matrix $\mathcal{S}_{\text{movie}}$:
\begin{align}
    b_n &\leftarrow \frac{\lambda \sum_{m \in \Omega_{\text{train}}^n} \left(r_{m,n} - \mu - a_m - u_m^\top v_n\right)}{\lambda |\Omega_{\text{train}}^n| + \gamma}, \label{eq:pmf_item_bias} \\
    v_n &\leftarrow \!\left(\lambda \!\! \sum_{m \in \Omega_{\text{train}}^n} \!\! u_m u_m^\top + \tau I_K\right)^{\!-1} \!\!\!\! \left(\lambda \!\! \sum_{m \in \Omega_{\text{train}}^n} \!\! \tilde{r}_{m,n}^{(v)} u_m\right)\!, \label{eq:pmf_item_vec}
\end{align}
where $\tilde{r}_{m,n}^{(v)} = r_{m,n} - \mu - a_m - b_n$. Because every coordinate step finds the exact minimum for that block of variables, the total loss $\mathcal{L}(\Theta)$ is guaranteed to go down at every iteration.

\subsection{Adding Movie Genres: Altered Loss Function and ALS Steps}
\label{sec:genre_model}

A clear weakness of standard matrix factorization appears when a movie is brand new ($|\Omega_{\text{train}}^n| = 0$) or has only a few ratings: because the prior on $v_n$ is centered at zero, \cref{eq:pmf_item_vec} sets $v_n = \mathbf{0}$ for any unrated movie. As a result, the dot product $u_m^\top v_n$ becomes zero, and the model cannot personalize predictions for new movies at all. To fix this, we incorporate the movie genre metadata directly into our model \cite{agarwal2009regression}.

In the MovieLens catalog, each movie $n$ is tagged with a set of genres $\mathcal{G}_n \subseteq \{1, \dots, G\}$ (for example, Adventure, Children, and Fantasy for \emph{Jumanji (1995)}; there are $G = 20$ genres in total, including an ``unlisted'' category). We assign each genre $g \in \{1, \dots, G\}$ its own latent trait vector $f_g \in \mathbb{R}^K$. Instead of centering the Gaussian prior of $v_n$ at zero, we center it at the normalized sum of the movie's genre vectors:
\begin{equation}
\bar{f}_n = \frac{1}{\sqrt{|\mathcal{G}_n|}} \sum_{g \in \mathcal{G}_n} f_g, \qquad v_n \,\big|\, F \;\sim\; \mathcal{N}\!\left(\bar{f}_n,\, \tau^{-1} I_K\right).
\label{eq:genre_prior_centroid}
\end{equation}
Dividing by $\sqrt{|\mathcal{G}_n|}$ keeps the variance of $\bar{f}_n$ constant whether a movie has $1$ genre tag or $5$ genre tags. Placing a Gaussian prior $f_g \sim \mathcal{N}(\mathbf{0}, \tau_f^{-1} I_K)$ on the genre vectors gives our altered loss function:
\begin{align}
\mathcal{L}_{\text{genre}} &= \frac{\lambda}{2} \!\sum_{(m,n) \in \Omega}\! \left(r_{mn} - \mu - a_m - b_n - u_m^\top v_n\right)^2 \nonumber \\
&\quad + \frac{\gamma}{2} \left( \sum_{m=1}^M a_m^2 + \sum_{n=1}^N b_n^2 \right) + \frac{\tau}{2} \sum_{m=1}^M \|u_m\|_2^2 \nonumber \\
&\quad + \frac{\tau}{2} \sum_{n=1}^N \left\| v_n - \bar{f}_n \right\|_2^2 + \frac{\tau_f}{2} \sum_{g=1}^G \|f_g\|_2^2.
\label{eq:genre_als_objective}
\end{align}

\textbf{Optimization Steps.} Because the new penalty $\frac{\tau}{2} \sum_{n=1}^N \|v_n - \bar{f}_n\|_2^2$ is quadratic in both $v_n$ and $f_g$, each ALS epoch cleanly splits into three alternating update steps:
\begin{enumerate}
    \item \textbf{Step 1: Update Users ($a_m, u_m$)}: Since the genre terms do not depend on $a_m$ or $u_m$, the user updates are identical to \cref{eq:pmf_user_bias,eq:pmf_user_vec}.
    \item \textbf{Step 2: Update Movies ($b_n, v_n$)}: The movie bias update $b_n$ is unchanged from \cref{eq:pmf_item_bias}. Taking the derivative of \cref{eq:genre_als_objective} with respect to $v_n$ and setting it to zero adds $\tau \bar{f}_n$ to the right-hand side of the movie vector update:
    \begin{equation}
    \begin{aligned}
    v_n \leftarrow &\left( \lambda \sum_{m \in \Omega^n} u_m u_m^\top + \tau I_K \right)^{-1} \\
    &\times \left( \lambda \sum_{m \in \Omega^n} \tilde{r}_{mn}^{(v)} u_m + \frac{\tau}{\sqrt{|\mathcal{G}_n|}} \sum_{g \in \mathcal{G}_n} f_g \right).
    \end{aligned}
    \label{eq:genre_item_vec_update}
    \end{equation}
    Equation~\eqref{eq:genre_item_vec_update} shows why this works so well:
    \begin{itemize}
        \item \emph{New / Cold-start movie} ($|\Omega^n| = 0$): The sum over ratings is zero, so $v_n \leftarrow (\tau I_K)^{-1} (\tau \bar{f}_n) = \bar{f}_n$. Even with zero ratings, a new movie immediately gets a meaningful trait vector built from its genres!
        \item \emph{Popular movie} ($|\Omega^n| \gg \tau / \lambda$): The rating sum $\lambda \sum_{m \in \Omega^n} u_m u_m^\top$ is much larger than $\tau I_K$, so the data dominates the prior and $v_n$ is learned freely from user ratings.
    \end{itemize}
    \item \textbf{Step 3: Update Genre Vectors ($f_g$)}: Holding the movie vectors $V = [v_1, \dots, v_N]^\top \in \mathbb{R}^{N \times K}$ fixed, let $B \in \mathbb{R}^{N \times G}$ be the movie--genre matrix where $B_{ng} = |\mathcal{G}_n|^{-1/2}$ if movie $n$ has genre $g$ and $0$ otherwise, so $\bar{f}_n = (B F)_{n,:}^\top$. Minimizing \cref{eq:genre_als_objective} with respect to $F = [f_1, \dots, f_G]^\top \in \mathbb{R}^{G \times K}$ is a simple ridge regression with exact solution:
    \begin{equation}
    F \leftarrow \left( \tau B^\top B + \tau_f I_G \right)^{-1} \left( \tau B^\top V \right),
    \label{eq:genre_matrix_update}
    \end{equation}
    or written for a single genre $g$ over the set of movies $\mathcal{I}_g = \{n : g \in \mathcal{G}_n\}$ with partial residual $\tilde{v}_n^{(-g)} = v_n - |\mathcal{G}_n|^{-1/2} \sum_{g' \in \mathcal{G}_n \setminus \{g\}} f_{g'}$:
    \begin{equation}
    f_g \leftarrow \frac{\tau \sum_{n \in \mathcal{I}_g} |\mathcal{G}_n|^{-1/2} \, \tilde{v}_n^{(-g)}}{\tau \sum_{n \in \mathcal{I}_g} |\mathcal{G}_n|^{-1} + \tau_f}.
    \label{eq:genre_coord_update}
    \end{equation}
\end{enumerate}
Because there are only $G = 20$ genres, solving the $20 \times 20$ system in Step 3 takes less than $2$~ms per epoch.

\subsection{Making ALS Fast on 32 Million Ratings}
\label{sec:fast_cholesky}

Running \cref{eq:pmf_user_vec,eq:pmf_item_vec,eq:genre_item_vec_update} on $25.6$ million training ratings per epoch requires building and solving $M + N = 285{,}380$ linear systems of size $K \times K$ in every iteration. A naive implementation in Python or vectorized array operations runs into a major memory bottleneck:
\begin{itemize}
    \item \textbf{Why Batched Array Operations Are Slow:} If we try to avoid loops by computing the outer products $v_n v_n^\top \in \mathbb{R}^{K \times K}$ for a batch of rows and summing them with segmented array reductions, the program has to allocate a 3D array of shape $(\text{ratings in batch}) \times K \times K$. For popular movies, a batch of rows can contain millions of ratings, which creates gigabytes of temporary arrays at every step and slows down memory access.
    \item \textbf{Parallel CSR Loops with In-Place Cholesky:} Instead of creating large temporary arrays, we compile the user and movie update loops to multi-threaded machine code. Each CPU thread processes one user $m$ (or movie $n$) at a time using a small thread-local matrix $A \in \mathbb{R}^{K \times K}$ and vector $b \in \mathbb{R}^K$ that fit directly inside the CPU cache (only $2$~KB of memory for $K=16$). As the thread scans through the user's CSR slice, it adds $\lambda v_n v_n^\top$ into the lower triangle of $A$. Because $A = \lambda \sum v_n v_n^\top + \tau I_K$ is symmetric and positive-definite whenever $\tau > 0$, we solve $A u_m = b$ in-place using Cholesky decomposition $A = L L^\top$:
    \begin{equation}
    \begin{aligned}
        L_{i,j} &= \frac{1}{L_{j,j}} \!\left(A_{i,j} - \sum_{p=1}^{j-1} L_{i,p} L_{j,p}\right) \quad (i > j), \\
        L_{i,i} &= \sqrt{A_{i,i} - \sum_{p=1}^{i-1} L_{i,p}^2},
    \end{aligned}
    \end{equation}
    followed by forward and backward substitution. Because $A$ is symmetric, we only compute half of the matrix entries, and solving via Cholesky takes half as many operations as standard Gaussian elimination without needing external LAPACK calls.
\end{itemize}

\section{Experimental Results}
\label{sec:experiments}

In this section, we present all of our experimental results on both the MovieLens-5M subset and the full MovieLens-32M dataset.

\subsection{Train/Test Split and Evaluation Setup}
To measure how well our models predict unseen ratings, we split the observed ratings $\Omega$ randomly using an $80\% / 20\%$ Bernoulli coin flip (with fixed random seed $42$) into a training set $\Omega^{\text{train}}$ ($25{,}604{,}307$ ratings on 32M; $4{,}000{,}446$ on 5M) and a test set $\Omega^{\text{test}}$ ($6{,}395{,}897$ ratings on 32M; $999{,}554$ on 5M). Both sets are stored in dual CSR format ($\mathcal{S}_{\text{user}}$ and $\mathcal{S}_{\text{movie}}$). We also construct a controlled cold-start split where $500$ movies ($73{,}217$ test ratings) have all of their training ratings held out ($|\Omega_{\text{train}}^n| = 0$) so we can directly test cold-start predictions.

We evaluate all models using the Root Mean Squared Error (RMSE) on both the training and test sets:
\begin{equation}
    \text{RMSE}(\Omega') = \sqrt{\frac{1}{|\Omega'|} \sum_{(m,n) \in \Omega'} \left(r_{m,n} - \hat{r}_{m,n}\right)^2}.
\end{equation}
Before training, latent vectors $u_m$ and $v_n$ are initialized from a normal distribution $\mathcal{N}(0, (0.1 / \sqrt{K})^2)$ with a fixed random seed so all comparisons are reproducible.
